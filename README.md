# KonspekAI

**KonspekAI превращает видео, аудиозаписи и текст в структурированные конспекты.** Сервис локально распознаёт речь с помощью Vosk, затем отдельно оформляет расшифровку и составляет конспект с помощью выбранной языковой модели.

![Проверки GitHub Actions](https://github.com/GadXx/konspekAI/actions/workflows/ci.yml/badge.svg)

## Возможности

- Принимает текст и загруженные видео- или аудиофайлы. Обработка ссылок не поддерживается.
- Распознаёт речь локально с помощью Vosk. По умолчанию настроен русский язык.
- Поддерживает Ollama, OpenAI и совместимые с OpenAI API, включая NVIDIA NIM.
- Создаёт содержательный, краткий или тезисный конспект.
- Возвращает структурированный JSON и готовое представление в Markdown.
- Предоставляет русскоязычное одностраничное веб-приложение на Vue и Tailwind.
- Автоматически сохраняет конспекты в личной библиотеке. Конспекты остаются там, пока пользователь их не удалит.
- Поддерживает папки, поиск и перемещение конспектов. Удаление папки также удаляет все конспекты в ней.
- Обрабатывает задания асинхронно через API и отдельный worker; хранит состояние в SQLite или PostgreSQL.
- Документирует API через Swagger и OpenAPI.

## Быстрый запуск

Требуются Docker Compose и Ollama с установленной моделью `qwen2.5:14b`.

```bash
cp .env.example .env
docker compose up --build
```

При первом запуске Compose загрузит небольшую русскую модель Vosk (около 45 МБ) в постоянный том. Для более точного распознавания можно указать большую серверную модель в `VOSK_MODEL_URL` (около 1,8 ГБ, требуется больше памяти). Модель Ollama при стандартном запуске берётся с хоста и повторно не скачивается.

На Linux Ollama часто принимает соединения только через loopback, недоступный из контейнера. Настройте адрес `OLLAMA_BASE_URL`, доступный только через Docker bridge, либо используйте профиль `ollama`. Не публикуйте незащищённый API Ollama во внешнюю сеть.

Откройте:

- Веб-приложение: <http://localhost:3000>
- Swagger UI: <http://localhost:3000/docs>
- OpenAPI JSON: <http://localhost:3000/openapi.json>
- Проверка состояния API: <http://localhost:3000/readyz>

Compose запускает API в режиме разработки: по умолчанию используется SQLite, а ответ задания включает распознанный текст и нормализованную расшифровку. В production по умолчанию выбирается PostgreSQL; задайте `POSTGRES_PASSWORD`, `DATABASE_URL` и `API_ACCESS_TOKEN` (случайное значение не короче 32 символов) в `.env`:

```bash
docker compose -f docker-compose.yml -f docker-compose.production.yml -f docker-compose.postgres.yml up --build
```

Производственный профиль ограничивает публикацию API локальным адресом, включает файловую систему только для чтения и снимает Linux capabilities. Перед доступом из интернета настройте TLS и доверенный обратный прокси. Диалект можно явно переопределить через `DATABASE_DIALECT=sqlite` или `DATABASE_DIALECT=postgres`; при явном выборе SQLite уберите файл `docker-compose.postgres.yml` из команды.

## Веб-приложение и библиотека

Созданный конспект автоматически появляется в библиотеке и не удаляется по истечении срока хранения задания. Библиотека пока одна на весь локальный экземпляр: учётных записей и многопользовательского хранения нет. Можно создавать папки, перемещать конспекты между ними, искать и удалять конспекты. Удаление папки безвозвратно удаляет и всё её содержимое.

В производственном режиме введите общий API-токен в настройках доступа веб-приложения. Ключи NVIDIA или других LLM-провайдеров нужны только worker-контейнеру; храните их в `.env` или в менеджере секретов.

## Провайдеры языковых моделей

Выбор провайдера делается при запуске через `LLM_PROVIDER`:

| Значение | Назначение | Основные настройки |
|---|---|---|
| `ollama` | Локальная модель Ollama; вариант по умолчанию | `OLLAMA_BASE_URL`, `OLLAMA_MODEL` |
| `openai-compatible` | OpenAI или совместимый API | `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL` |
| `nvidia` | NVIDIA NIM | `NVIDIA_BASE_URL`, `NVIDIA_API_KEY`, `NVIDIA_MODEL` |

Для NVIDIA по умолчанию используется `nvidia/nemotron-3.5-lightning-30b-a3b`. Параметры моделей OpenAI-совместимых провайдеров можно переопределить отдельно для нормализации и составления конспекта: `LLM_NORMALIZATION_MODEL` и `LLM_SUMMARY_MODEL`.

### Запуск Ollama в Compose

Изолированный профиль Ollama использует собственный том и самостоятельно загружает модель. Он не обращается к кэшу Ollama на хосте.

```bash
docker compose --profile ollama -f docker-compose.yml -f docker-compose.ollama.yml up --build
```

### Явный запуск с PostgreSQL в режиме разработки

SQLite подходит для одного локального worker. Для нескольких worker используйте PostgreSQL:

```bash
docker compose --profile postgres -f docker-compose.yml -f docker-compose.postgres.yml up --build
```

Задайте надёжные `POSTGRES_PASSWORD` и `DATABASE_URL` в `.env`. Пароль внутри URL должен быть закодирован в процентах. Для рабочей установки также настройте резервное копирование и проверку восстановления.

## API

Создать задание можно через `POST /api/v1/jobs`. В JSON передаётся текст, в `multipart/form-data` — один файл и параметры языка. Допустимые типы конспекта: `detailed`, `brief`, `bullet_points`.

```bash
curl -X POST http://localhost:3000/api/v1/jobs \
  -H 'Content-Type: application/json' \
  -d '{"text":"Текст лекции о работе очередей.","language":"ru","summary_type":"detailed"}'
```

API отвечает `202 Accepted` с идентификатором задания и адресами для проверки состояния и получения результата. В производственном режиме передавайте заголовок `Authorization: Bearer <API_ACCESS_TOKEN>`.

`RATE_LIMIT_MAX` ограничивает отдельно каждый маршрут, который меняет данные. Частые запросы на чтение состояния, результата и библиотеки лимит не расходуют.

Полное описание методов, форматов и кодов ошибок доступно в [руководстве по API](docs/api.md) и в Swagger.

Поддерживаемые расширения: `.wav`, `.mp3`, `.m4a`, `.aac`, `.ogg`, `.opus`, `.flac`, `.wma`, `.mp4`, `.mkv`, `.mov`, `.webm`, `.avi`, `.m4v`. Размер файла, длительность записи, максимальный объём текста и срок хранения заданий настраиваются через переменные среды. Текущие значения и описание переменных приведены в [`.env.example`](.env.example).

## Хранение данных

Распознавание речи выполняется локально. Расшифровка отправляется выбранному провайдеру LLM для нормализации и составления конспекта. При использовании Ollama обработка остаётся на настроенном сервере Ollama; OpenAI-совместимый провайдер получает исходный текст запроса.

Состояние, текст и результат задания хранятся в базе заданное число дней (`JOB_RETENTION_DAYS`, по умолчанию 7). Исходный медиафайл удаляется после успешного распознавания или окончательного сбоя. Сохранённые в библиотеке конспекты не имеют срока автоматического удаления.

## Разработка

Требуются Node.js 22 или новее и npm.

```bash
npm ci
npm run db:migrate
npm run lint
npm test
```

Для запуска API и worker напрямую предварительно выполните миграции один раз. В Compose это делает отдельный одноразовый контейнер. Тесты проверяют API-контракты, ввод и валидацию, библиотеку, очереди, провайдеры LLM и разбиение текста; они не запускают реальное распознавание Vosk или генерацию Ollama. GitHub Actions дополнительно проверяет зависимости, настройки Compose и сборку Docker-образа.
